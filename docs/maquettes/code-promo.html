Code promo du Pass

Le code promo se saisit dès la liste des Pass (E1), juste sous le bandeau du répétiteur, pour voir l'effet sur chaque Pass. Il est repris, déjà appliqué, sur l'écran de paiement (E2), où le lien « J'ai un code promo » remonte juste sous la carte du Pass, avant le choix de l'opérateur. On garde les deux écrans Figma et on n'ajoute que ce que le code change. Essaie le prototype : les deux écrans partagent le même code.

Prototype cliquable

Touche une carte pour choisir un Pass, « J'ai un code promo » pour ouvrir le champ. Le code appliqué sur l'un des écrans apparaît sur l'autre.

Codes de démonstration

Touche un code pour le mettre dans le champ ouvert (sur E1 si rien n'est ouvert), ou tape-le. ELEARN20 : -20 % ; BIENVENUE500 : -500 FCFA (le Pass semaine passe à 0) ; CONCOURS : seulement le Pass concours. Cinq essais ratés de suite donnent « Trop d'essais ».

Spec pour le dev

  

    
Ce qui change par rapport à Figma
    
      
  • E1 : un bloc code promo est ajouté juste sous le bandeau « répétiteur », avant les cartes. Aucune carte ne change de place ; seul leur prix change quand un code est appliqué.
    • 
      
  • E2 : « J'ai un code promo » quitte le bas de l'écran. Il se place juste sous la carte du Pass (résumé), avant « Ton opérateur ».
    • 
      
  • Le texte du bandeau est celui de Figma E1, à vérifier au codage.
    • 
    

    
Règles retenues
    
      
  • Un seul code par paiement. Pour en changer, on retire le code appliqué, puis on en saisit un autre.
    • 
      
  • Valable pour les Pass payants (semaine, mois, concours), jamais pour « Gratuit », ni pour les crédits ou d'autres achats.
    • 
      
  • Le code est unique pour toute la session de paiement : saisi sur E1, il est déjà appliqué sur E2. Saisi sur E2, il est aussi retrouvé en revenant sur E1. Retiré d'un côté, il l'est des deux.
    • 
      
  • Il reste appliqué quand l'élève revient en arrière ou change de Pass. Il est envoyé à la création de la commande, seulement s'il est valable pour le Pass choisi.
    • 
      
  • À l'ouverture de E2, le code est revérifié sans bruit. S'il n'est plus valable (expiré, épuisé entre-temps) : il est retiré, un message « Ce code n'est plus valable » s'affiche et les prix redeviennent normaux.
    • 
      
  • Le prix est toujours recalculé côté serveur : l'app affiche ce que le serveur renvoie et ne l'envoie jamais.
    • 
      
  • Vérification au toucher sur « Appliquer » ou sur la touche OK du clavier, pas à chaque lettre. Une seule requête à la fois.
    • 
      
  • Majuscules, sans espaces, 20 caractères au plus (lettres, chiffres, tiret).
    • 
      
  • La réduction est « réservée » à la commande ; used_count n'augmente qu'au paiement confirmé par le serveur (issue #7).
    • 
    

    
E1 · comportements
    
      
  • Ouverture : « J'ai un code promo » remplace le lien par le champ, ouvre le clavier. L'écran défile pour garder le champ et les cartes visibles au-dessus du clavier.
    • 
      
  • Annuler : referme le champ, efface le texte, rend le lien.
    • 
      
  • Appliquer : blanc et grisé tant que le champ est vide, vert dès qu'il y a du texte. « Payer » passe alors en blanc : un seul bouton vert par écran. Pendant la vérification : « Vérification », champ figé.
    • 
      
  • Appliqué : le champ laisse place à une ligne avec le code, l'effet (« -20 % sur les Pass payants ») et « Retirer ». Chaque carte payante montre l'ancien prix barré, le nouveau prix et un badge (« -20 % » ou « -500 FCFA »).
    • 
      
  • Code valable pour un seul Pass : seule cette carte change ; les autres payantes portent « Code non valable pour ce Pass » (texte et icône, pas seulement la couleur) et gardent leur prix.
    • 
      
  • Rabais qui couvre tout : la carte affiche 0 FCFA ; si elle est choisie, le bouton devient « Activer mon Pass ».
    • 
      
  • Bouton principal : « Payer » suit le Pass choisi et son prix après code. « Envoyer à mon parent » reste en blanc, le code est joint au lien (à confirmer par Benny : le parent voit alors le prix réduit).
    • 
      
  • Erreur : le texte reste dans le champ, bordure et message en corail, message annoncé au lecteur d'écran. Dès que l'élève modifie le texte, l'erreur disparaît. Les prix normaux restent affichés et payer reste possible.
    • 
    

    
E2 · comportements
    
      
  • Ordre : résumé du Pass, code promo, opérateur, numéro, aide, bouton « Payer ».
    • 
      
  • Code repris de E1 : la ligne « appliqué » est déjà là, le résumé montre prix barré, nouveau prix et badge, plus « Tu économises … ».
    • 
      
  • Sans code : le lien « J'ai un code promo » ouvre le champ avec les mêmes états que sur E1.
    • 
      
  • Code non applicable au Pass choisi (ex. CONCOURS avec le Pass mois) : la ligne passe en neutre avec « Valable pour le Pass concours seulement », le prix reste normal. Deux choix : « Choisir le Pass concours » (retour sur E1, carte sélectionnée) ou « Retirer ».
    • 
      
  • Prix à 0 FCFA : plus d'opérateur ni de numéro. Une carte verte dit « Rien à payer » et le bouton devient « Activer mon Pass ».
    • 
      
  • Aucune demande Mobile Money n'est envoyée à 0 FCFA : le serveur active le Pass directement, dans la même transaction que le code consommé. Le compte connecté reste obligatoire.
    • 
      
  • Le reçu (E4) montre le prix barré, le code, le montant payé (0 FCFA possible).
    •

Accessibilité et style
    
      
  • Champ avec libellé « Code promo », majuscules automatiques, sans correction automatique, touche clavier « OK » = Appliquer.
    • 
      
  • L'état « appliqué », « non valable » et les erreurs portent un texte et une icône, jamais la couleur seule.
    • 
      
  • Cartes de Pass : rôle radio, état « sélectionné » annoncé ; prix annoncé « 2 000 FCFA au lieu de 2 500 FCFA ».
    • 
      
  • Cibles de 48 px, texte noir sur le jaune du badge, aucun emoji, icônes Lucide.
