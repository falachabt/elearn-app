## 0. Comment lire et utiliser ce document

### 0.1 Règle anti-dérive (obligatoire)
Il existe trois sources qui ne doivent jamais diverger : ce cahier, la maquette, le code. Une seule voie de modification :
1. **Le changement est écrit dans ce cahier** (une ligne dans le journal des changements, section 11, avec date, auteur, identifiants d'écran touchés, raison).
2. **La maquette est mise à jour** (agent design) et son identifiant d'écran est repris ici.
3. **Le code est modifié**, avec le test qui prouve la règle, et l'identifiant de l'exigence dans le nom du test ou son commentaire.
Interdit : coder un écart « parce que c'est plus simple », corriger la maquette sans toucher au cahier, ou modifier le cahier sans maquette. Si le code découvre un cas non prévu, le développeur écrit la question dans la section 10 et attend la réponse ; il n'invente pas.
Toute exigence porte un identifiant stable. Une exigence supprimée est marquée « retirée » dans le journal, jamais réutilisée.
Chaque pull request ou commit qui touche le profil TOEIC cite les identifiants d'écran et d'exigence. (Pas de PR pour l'app : commit direct sur la branche de travail, selon la règle de Benny.)

### 0.2 Identifiants d'écran
Les identifiants sont ceux de la maquette version 2 (`docs/maquettes/toeic-revue-complete.md`, commit `ced993c`, états du moteur d'exercice `9148a7b`, navigation N1 à N3 `b74a711`, options de réponse v4 `1953b17`) : `TOEIC-<section><n>`, stables, jamais renommés. Dans ce cahier, le préfixe `TOEIC-` est omis (A1 = TOEIC-A1). Sections : **N** navigation (accueil, Réviser, Moi) ; **A** arrivée, objectif, diagnostic ; **B** moteur d'exercice ; **C** réviser ; **D** parcours du jour ; **E** test blanc ; **S** états transverses ; **X** écrans ajoutés ; **B*-CHARGE / -AUDIO-KO / -ERR-AUDIO** états du moteur.
Correspondance avec les premiers noms : O1 = A1, O2 = A2, O3 = A3, ancien A3 « temps par jour » = A4, O4 = A5.

### 0.3 Lots de livraison (voir `planning.md`)
Chaque écran porte un lot : **S1** (semaine 1, version réduite), **S2** (semaine suivante), **V2** (tests blancs, hors ligne des packs). Un écran absent du lot en cours n'est pas codé, et le bouton qui y mène est absent (jamais désactivé en silence) : voir D-01 à D-04 du journal.

### 0.4 Statut « maquette à venir »
Tout ce qui n'est pas dessiné est marqué **[maquette à venir]**. Le développeur ne le code pas tant que la maquette n'est pas livrée et reportée ici, sauf comportement purement technique (aucune interface nouvelle). Les états de chaque écran (vide, erreur, hors ligne, squelette, crédits épuisés) sont presque tous dans ce cas : voir 3.2.

## 2. Règles transverses (s'appliquent à chaque écran, sauf mention contraire)

- **R-01 Interface** : aucun emoji ; icônes Lucide carrées, trait 2 ; tokens `theme.color.*` uniquement ; une seule action verte par écran ; texte noir sur surface colorée ; cibles de 48 px minimum espacées de 8 px ; tutoiement ; espace insécable avant `?` `!` `:` ; texte qui suit la taille système jusqu'à 130 %.
- **R-02 Thèmes** : chaque écran existe en clair et en sombre. Exception : l'**épreuve** (E1 à E5) reste sombre dans les deux thèmes.
- **R-03 États sans couleur seule** : chaque état porte un texte et une icône (Fragile, En progrès, Acquise, Pas commencée, Juste, Faux). Une option **sélectionnée** n'affiche plus de libellé ni de coche (maquette v4) : elle est portée par le fond vert, un contour de 3 px et une lettre inversée ; le lecteur d'écran annonce « Choisi ».
- **R-04 Montants** : aucun montant (crédits, coûts, seuils, paliers, délais) dans le code, les textes ou les tests. Les valeurs de la maquette sont des exemples. Lus dans `credit_settings`, `credit_actions` et `cert_settings`.
- **R-05 Score** : jamais présenté comme officiel ; toujours une fourchette ; mention « Une estimation, pas un score officiel. » partout où un score apparaît.
- **R-06 Marque** : mention « TOEIC est une marque d'ETS. Elearn Prépa n'est pas affilié à ETS. » sur A2 et dans « À propos » ; jamais de logo ETS ; logo fourni par Benny, sinon emplacement (voir écart E-05).
- **R-07 Hors ligne** : le contenu préparé est valable `{offline_validity_days}` jours (initial 7) sans contact serveur, puis S9 (contenu expiré).  toute lecture d'une clé locale de contenu passe par `lireLocalHorsLigne()` (AGENTS.md §16 bis) ; toute nouvelle clé locale est ajoutée à la liste de ce paragraphe et à `reviser.test.ts`. Toute action qui exige le serveur passe par `useGardeReseau`. Les écritures de réponses, de mots et de séances sont mises en file locale et rejouées de façon idempotente (`client_uuid`).
- **R-08 Sécurité des données** : tables `cert_user_*` avec RLS dès la création (accès limité à `auth.uid()`), écritures uniquement par RPC, tests pgTAP d'isolation entre deux comptes. Le corrigé payant est servi par le serveur après vérification du droit (option A).
- **R-09 Mesure** : tout évènement est typé dans `src/services/evenements.ts` ; les propriétés sont celles de la section 7. Drapeau PostHog `cert_profile_enabled` : s'il est faux, la carte « Je prépare une certification » (A1) n'est pas affichée.
- **R-10 Retours** : sons et vibrations passent par `useFeedback`, réglables ; jamais de son en direct dans un écran. L'épreuve n'en joue aucun pendant l'écoute.
- **R-11 Contenu** : question, notion, mot : statut `reviewed` obligatoire pour être servi à un élève. Un contenu en `draft` n'est jamais renvoyé par les RPC de lecture.
- **R-12 Conteneur** : tout écran avec saisie passe par `Ecran` (AGENTS.md §12). Barre d'état et barre de navigation selon le thème.
- **R-13 Tests** : chaque exigence a au moins un test nommé avec son identifiant. Jest pour l'app, pgTAP pour la base, Deno pour les Edge Functions (`npx supabase@2.118.0 test db` avant toute migration poussée). Jamais de valeur de crédit figée dans un test.

## 4. Formules et règles métier

Tous les paramètres entre accolades sont dans `cert_settings` (clé/valeur JSON, lue par RPC, modifiable au back-office sans déploiement). Les valeurs données sont des **valeurs initiales de seed**, pas des constantes de code.

### F1 Estimation du score sur 990
- Sections : Listening = P1 à P4, Reading = P5 à P7.
- Pour une section : `p = bonnes / répondues` (hors questions passées, comptées fausses).
- `Score_section = clamp(5, 495, 5 + 490 × p)`, arrondi au multiple de 5 le plus proche. Total = Listening + Reading.
- Cette règle reprend la démo (5 + 4,9 par bonne réponse sur 100) : elle est **approximative**. Si ETS publie une table de conversion utilisable, elle remplace F1 via `{score_table}` sans changer l'écran.

### F2 Fourchette
- Pour chaque section avec `n` questions répondues, intervalle de Wilson à `{score_z}` (valeur initiale 1,28, soit 80 %) sur `p` ; bornes converties par F1 ; fourchette totale = somme des bornes basses et hautes, arrondie à 10 (basse vers le bas, haute vers le haut), bornée à [10, 990].
- L'estimation n'est disponible qu'à partir de `{score_min_answers}` réponses au total (initial 20, toutes sections confondues, diagnostic compris) ; en dessous, S8 (« Il faut au moins 20 réponses pour estimer ton score. Tu en es à {k}. », barre `k / 20`) ou la mention A5 / S7 si aucune réponse. Si une section a 0 réponse, l'intervalle de Wilson de cette section est [0 ; 1] (fourchette maximale).
- **Conséquence à connaître** : avec 20 questions (10 par section) la fourchette est large (de l'ordre de 150 points de chaque côté). La maquette affiche « 745 » (80 points) : voir écart E-03. **Décision D-10 (Benny, 15 octobre)** : la fourchette honnête (environ 150 points de chaque côté) est retenue et toujours présentée comme « Une estimation ». Le diagnostic pourra être prolongé plus tard par une suite de questions pour resserrer la fourchette, sans changer la maquette : même écran, seule la largeur change.

### F3 Maîtrise d'une notion
- Réponses de l'élève sur les questions étiquetées par la notion (rôle principal poids 1, secondaire poids 0,5). Les réponses au diagnostic comptent comme les autres.
- Poids de récence : `w = 0,5 ^ (âge_en_jours / {mastery_halflife_days})` (initial 14).
- `M = Σ(poids_rôle × w × juste) / Σ(poids_rôle × w)`.
- États : 0 réponse → **Pas commencée** ; sinon `M < {mastery_fragile_below}` (initial 0,40) → **Fragile** ; `M ≥ {mastery_acquired_from}` (initial 0,70) → **Acquise** ; sinon **En progrès**.
- Décompte affiché : « {n} questions · {r} réussies » avec `n` et `r` bruts (non pondérés).

### F4 Maîtrise d'une partie (carte de maîtrise)
- `M_partie` = même formule que F3 sur toutes les réponses de la partie (pas la moyenne des notions). Barre = `M_partie × 100`, mêmes états et seuils que F3.
- Regroupement du résumé du diagnostic (A7) : « P1 à P2 », « P3 à P4 », P5, P6, P7 (cinq lignes).
- Sur C2 : sept lignes, une par partie. Les deux totaux (« Acquise {a} », « En progrès {p} », « Fragile {f} », « Pas commencée {c} ») comptent des **notions**, pas des parties.

### F5 Carnet de mots (boîtes de Leitner)
- Un mot entre au carnet en **boîte 1** : par ajout manuel (C6), par « mot clé à ajouter » (B9), par échec sur une question qui référence ce mot, ou par la raison « Je ne connaissais pas le mot » (B10).
- Réussite (séance de mots « Je savais », ou question juste référençant le mot) : `boîte = min(4, boîte + 1)`. Échec (« Je ne savais pas », ou question fausse) : `boîte = 1`.
- Échéance : `prochaine_revue = aujourd'hui + {box_delays_days}[boîte]` (initial 1, 3, 7, 14 jours pour les boîtes 1 à 4).
- États : boîte 1 = **À revoir**, boîtes 2 et 3 = **En cours**, boîte 4 = **Connu**.
- Un mot « échu » est un mot dont `prochaine_revue ≤ aujourd'hui`. Les mots échus alimentent la séance du jour (F7) et la séance de mots.
- Séance de mots : `{words_session_size}` mots (initial 10), choisis parmi les échus, dans l'ordre boîte croissante puis échéance la plus ancienne ; si moins que la taille, la séance est plus courte ; s'il n'y a aucun mot échu, la séance n'est pas proposée (ES-2 de C6).

### F6 Rejeu des questions ratées
- Une question ratée est planifiée à J+1. Chaque revue juste la fait passer au délai suivant de `{replay_delays_days}` (initial 1, 3, 7) ; après `{replay_remove_after}` réussites de suite (initial **2**) elle est retirée du rejeu ; une erreur la ramène à J+1 et remet le compteur à zéro. Avec la valeur initiale, les délais utilisés sont J+1 puis J+3 ; J+7 ne sert que si `replay_remove_after` est porté à 3 (réglage, sans déploiement).
- Source de la question « à rejouer » : `cert_user_question.prochaine_revue ≤ aujourd'hui`.

### F7 Composition de la séance du jour
- Durée choisie : 10, 20 ou 30 minutes (A3, modifiable dans D4). Le temps est **au choix de l'élève** (décision de Benny, 15 octobre).
- Quatre blocs dans cet ordre fixe : **Cours**, **Mots**, **Rejeu**, **Série**. Un bloc sans contenu disponible est omis (jamais affiché vide).
- Budget par durée (`{session_budget}`, valeurs initiales) :

| Durée | Cours | Mots | Rejeu | Série |
| --- | --- | --- | --- | --- |
| 10 min | 1 notion (3 min) | jusqu'à 4 mots | jusqu'à 3 questions | 5 questions |
| 20 min | 1 notion (3 min) | jusqu'à 6 mots | jusqu'à 4 questions | 10 questions |
| 30 min | 1 notion (5 min) | jusqu'à 10 mots | jusqu'à 8 questions | 15 questions |

- **Choix de la notion de cours** : la notion de maîtrise la plus basse (F3) parmi celles de l'élève ayant au moins une réponse fausse dans les `{recent_days}` derniers jours (initial 14) et dont la fiche n'a pas été ouverte depuis `{notion_cooldown_days}` jours (initial 3) ; à égalité, la plus grande somme d'erreurs récentes. Sans réponse récente : la première notion « Pas commencée » dans l'ordre du référentiel.
- **Choix de la série** : la partie de plus faible maîtrise (F4), différente de celle de la veille si possible ; la série porte sur les questions de la partie non encore vues d'abord.
- **« Pourquoi cette séance ? »** : phrase construite par gabarit à partir de la première condition vraie : « Parce que tu as raté {n} questions sur {notion} » (`n` = erreurs récentes sur la notion de cours) ; puis, si des mots sont échus : « , et que {m} mots du carnet arrivent à échéance » ; sinon fin de phrase par un point. Sans erreur récente ni mot échu : « Pour continuer ton plan. » (texte à confirmer, écart E-10).
- Avancement : « {k} sur {b} terminés » où `b` = nombre de blocs présents et `k` = blocs terminés.
- Une séance est enregistrée avec sa composition (`cert_sessions.composition`) et un `client_uuid`.

### F8 Jours avant le test
`jours = date_test − aujourd'hui` en jours calendaires locaux de l'appareil. Si `date_test` absente : la ligne « Test dans » n'est pas affichée. Si `jours < 0` : état « date passée » (écart E-09).

### F9 Objectif
- Paliers rapides servis par `cert_exams.goal_steps` (initial 600, 700, 800, 900) ; un seul actif ; défaut 800.
- Valeur libre : entier entre 10 et 990 (bornes de la maquette) ; la saisie libre et le curseur partagent la même valeur ; un palier est mis en évidence s'il est égal à la valeur.
- La date du test est facultative, strictement postérieure à aujourd'hui.

### F10 Crédits
La règle des crédits et du Pass est la **section 12** (montants définitifs et gains : 12.6, décision D-11 ; les options A et B de 12.2 sont historiques). En attendant la décision, le code n'implémente aucun débit autre que ceux de la section 12.1 (communs aux deux options).

### F11 Statistiques (page 5.ST)
Toutes les valeurs sont calculées sur les réponses `cert_answers` de l'élève, à partir de F1 à F5 ; aucune nouvelle table de score.
- **Période** `P` (segments de la maquette) : Semaine = 7 jours glissants, Mois = 30 jours glissants, Tout = depuis l'inscription. Une réponse compte dans la période si sa date (jour local de l'appareil, enregistré à l'écriture) y est comprise. Défaut : 7 jours.
- **Taux de réussite** (global, par section, par partie) : `bonnes / répondues` sur `P`, arrondi à l'entier en pourcent ; s'affiche à partir de `{stats_min_answers}` réponses (initial 5), sinon « Pas assez de réponses ».
- **Score estimé et courbe** : F1/F2 sur toutes les réponses pour le chiffre courant. La courbe est une barre par semaine (par mois en « Tout ») : milieu de la fourchette F2 calculée sur les réponses jusqu'à la fin de la période de la barre, affichée à partir de la deuxième semaine, une barre n'existant que si `{score_min_answers}` réponses sont atteintes. Les réponses d'un mini-test par partie sont exclues du score (E-38) mais comptent dans les taux et la maîtrise.
- **Tendance** : milieu de la dernière fourchette moins milieu de la précédente ; `en hausse` si ≥ `{trend_min_points}` (initial 20), `en baisse` si ≤ −20, sinon `stable` ; absente avec moins de 2 tentatives.
- **Maîtrise par partie** : F4. **Notions fragiles** : les `{stats_top_notions}` (initial 5) notions de plus basse maîtrise F3 parmi celles qui ont au moins 3 réponses, état Fragile ou En progrès. **Notions en progrès** : les 3 notions dont `M` a le plus gagné sur `P` (comparaison de `M` calculé à la fin de `P` et au début de `P`) ; absent si `P` = « Tout » ou si l'historique est insuffisant.
- **Temps passé** : minutes actives (séances terminées, pauses exclues) plus temps de lecture des fiches de cours, sur `P`, affiché « {h} h {mm} » avec le détail séances / cours. **Régularité** : « {j} jours sur 7 » = jours locaux distincts des 7 derniers jours avec au moins une séance terminée ; séances terminées sur `P` ; **série de jours** = jours locaux consécutifs avec au moins une séance terminée jusqu'à aujourd'hui ou hier (même définition que le gain `streak_7`, 12.6.3) ; aucun message de culpabilité en cas de série cassée.
- **Carnet de mots** : nombre de mots par boîte F5 (À revoir 1, En cours 2 à 3, Connu 4) et mots passés de À revoir à Connu sur `P`.
- **Temps par question** : moyenne de `cert_answers.ms` par section sur `P`, en ignorant les valeurs supérieures à `{answer_ms_cap}` (initial 180 000 ms) ; comparée à la durée par question du vrai test (Listening 100 questions en 45 min, Reading 100 en 75 min, soit 27 et 45 secondes) *(seed `cert_exams`)*.
- **Écart à l'objectif** : `objectif − borne basse de F2`, affiché seulement avec une fourchette valide et un objectif (F9) ; « Objectif atteint » si la borne basse est au moins égale à l'objectif.

### 5.B Moteur d'exercice

**Principes communs aux sept types (B1 à B7)** · lot S1, sauf mention.
- **Entrée** : série d'entraînement (depuis C3, C5, D2), diagnostic (A6), rejeu (D2), test blanc (E2, E4 en V2). **Sortie** : question suivante ; après la dernière, B11 (série) ou A8 (diagnostic) ; quitter → X3.
- **Données** : une question `cert_questions` (type, partie, énoncé, options, bonne réponse, notion principale et secondaires, mots clés, explication, piège), audio/image si besoin, via RPC de série `cert_series_get(...)`. - **Évènements** : `cert_exercise_answered { type, partie, juste }` à chaque validation.
- **Tests communs** : Jest par type (rendu des états Choisi, Juste, Faux, désactivation, file locale), pgTAP `cert_series_get` (ne renvoie pas la bonne réponse avant la réponse).

2. Conversion : pour chaque question, un niveau de difficulté calibré (par exemple un modèle à un ou deux paramètres) est estimé à partir des réponses réelles de la banque. Le nombre de bonnes réponses pondéré par cette difficulté donne le score brut, puis le score de section par une table de conversion propre à la banque.
3. La table doit être calibrée sur des résultats réels anonymisés. Tant qu'elle ne l'est pas, l'écran affiche une fourchette et la mention « estimation provisoire ». Aucune table tierce n'est copiée dans l'app.
4. Marge d'erreur : interne seulement (taille de l'échantillon calibré). Elle n'est pas affichée à l'élève. L'écran affiche le chiffre net et la mention discrète « Estimation, pas un score officiel. »
5. Évolution : chaque test terminé met à jour l'estimation et sa marge. L'écran dit « tu étais à 745 au diagnostic ». La marge se réduit avec les tests terminés.

**Textes à valider** : « Ton score estimé » (titre) ; « Estimation, pas un score officiel. » ; « +15 depuis le diagnostic (745) » ; « Ton score bouge à chaque test terminé. Un test complet le précise le plus. »

### 5.M.3 La correction sur l'écran de la question (décision D-28)
- **Principe** : l'écran de la question ne change pas d'écran. Le contexte (photo, lecteur audio, passage ou documents, onglets de groupe, énoncé, options) reste à sa place, en haut ; la correction s'ouvre **en dessous**, dans la même zone de défilement. Il n'y a plus d'écran « Explication » séparé.
- **Séquence en Entraînement** : l'élève choisit puis touche « Valider » ; les options passent à « Juste » (coche et mot) et « Faux » (croix et mot) ; la carte de correction apparaît sous les options (animation désactivée avec « Réduire les animations ») ; le défilement amène le haut de la carte à l'écran et le lecteur d'écran annonce « Juste » ou « Faux » ; le bouton principal devient « Question suivante » ; le bouton « Quitter » reste X3.
- **Contenu de la carte de correction** (reprend B9, carte jaune doux `theme.corrige`) : badge « CORRIGÉ » ; « Bonne réponse : B · … » ; « Ta réponse : C » (omis si juste) ; « Notion : … » ; « Piège : … » ; chips de mots clés (ajout au carnet, F5) ; **« Transcription »** (repliée, parties 1 à 4 seulement, gratuite, D-30) ; liens « Revoir la notion » (gratuit, C5) ; bouton **« Explication détaillée »** avec badge de coût (1 crédit, masqué avec le Pass) ; « Pourquoi j'ai raté ? » (B10, S2).
- **« Explication détaillée » sans quitter l'écran** : le toucher ouvre la feuille de coût X5 (feuille du bas par-dessus l'écran de la question) ; après confirmation, le texte s'insère **dans la carte**, sous le piège, sans changer d'écran ; le débit est idempotent (AC-X1-3).
- **Contexte conservé selon le type** : photo (B1) toujours visible, zoom possible ; audio (B2 à B4) : lecteur visible avec « Réécouter » actif après validation ; passages (B5 à B7) : texte et onglets de documents inchangés, la phrase ou le trou concerné reste surligné ; **groupes (5.G)** : les onglets de question restent, la correction s'affiche dans l'onglet de la question validée, la validation du groupe suit 5.M.10 (un seul « Valider (k/N) »).
- **Petits écrans** : si le contexte et la carte dépassent l'écran, le contexte garde une bande réduite (lecteur audio ou vignette de photo) collée en haut pendant le défilement.
- **Hors ligne** : en Entraînement, la correction gratuite (bonne réponse, notion, piège, transcription) est incluse dans le contenu préparé de la série ; l'explication détaillée exige le serveur (règle du 7 octobre, comme X5).

### 5.M.4 La revue de fin en Examen, avec le contexte (décision D-28)
- Après la dernière question : écran de fin existant (B11 ou bilan de test : score, grille juste/faux avec numéros) puis « Revoir mes réponses ».
- **La revue réutilise l'écran de la question** en état « revue » : mêmes composants (photo, lecteur audio, passage, onglets de groupe, énoncé, options), réponse de l'élève et bonne réponse marquées « Juste » ou « Faux » en mots, carte de correction identique à 5.M.3 sous les options. Il n'y a pas d'autre écran d'explication.
- Navigation : grille cliquable en tête de revue (numéros, état par icône et mot), « Question suivante » et « Question précédente » ; les questions d'un même groupe restent groupées ; « Réécouter » disponible (l'écoute unique ne vaut que pendant l'épreuve).
- **Filtre** : « Toutes · Mes erreurs » (défaut : Mes erreurs s'il y en a, sinon Toutes).
- **Hors ligne** : une épreuve jouée hors ligne enregistre les réponses ; la correction exige le serveur (le contenu d'examen ne contient pas les bonnes réponses) : état « La correction sera disponible au retour du réseau. », à dessiner (écart E-55).
- **Diagnostic** : même revue (`TOEIC-S-REV-DIAG`), explications détaillées gratuites (D-09).

Lecture : texte seul, aucun crédit audio. Notions : 42 notions sont sous le seuil de 12 questions étiquetées, les 800 questions doivent les combler en priorité. Relecture humaine avant `reviewed`.
  - Décision proposée : démarrer avec **6 demi-tests par moitié** (contenu existant), cible 7 puis davantage quand le lot de 800 questions est généré, lot par lot.
- **Écrans à dessiner (brief au design, addendum du 22 octobre 4)**, clair et sombre : `TOEIC-V35-DEMI-ACCUEIL` (écran Demi-test de la capture : deux cartes Écoute et Lecture avec « 2 sur 7 faits » et meilleur score de la section), `TOEIC-V35-DEMI-LISTE-ECOUTE` et `TOEIC-V35-DEMI-LISTE-LECTURE` (liste des demi-tests : numéro, statut, scores, tentatives, date, « {n} questions nouvelles pour toi », « Conseillé », « Bientôt »), `TOEIC-V35-DEMI-DETAIL` (un demi-test : tentatives, « Refaire », « Reprendre », revue), et la ligne « Demi-tests faits » dans Statistiques. ## Banque de questions unique (version 1.34, 22 octobre 2026)

Décision de Benny (22 octobre, validation des demi-tests multiples) : les questions servent aussi à valider des notions et dans les parties ; on veut une banque de questions, pas un stock par test.

- **D-49 Principe** : `cert_questions` est la **seule** source de questions. Chaque question `reviewed` peut être utilisée partout : demi-tests, tests complets, mini-tests (par partie et mixte), séries et séances de révision, quiz de validation d'une notion ou d'un piège (F13), parties de Réviser, rejeu (F6), plan de formation (D-42). Un test, un demi-test ou une série n'est qu'une **composition** (liste de références vers la banque), jamais une copie. Une correction d'une question vaut donc partout.
- **Ce que le modèle permet déjà** : type, partie, notion principale et notions secondaires (5.T.2, poids 1 et 0,5), mots clés, piège, statut `reviewed`, groupes et passages ; les tests et demi-tests sont des tables de liens (`cert_test_questions`, `cert_half_test_questions`). Les séries et mini-tests tirent déjà dans la banque (`cert_mini_draw`).
- **Ce qui manque (additif)** :
  - `cert_questions.difficulty` (0 à 5, nullable, calibré plus tard par les réponses réelles, 5.R) ; en attendant, tirage sans difficulté.
  - **Compteur d'usage calculé, pas stocké** : vue `cert_question_usage(question_id, tests, demi_tests, mini, series, validations)` à partir des liens et des réponses, pour éviter toute dérive ; sert à D-46 (questions les moins utilisées) et au tirage de validation.
  - **Étiquette d'emploi** `cert_questions.usages` (tableau : `test`, `serie`, `validation`, `mini`) pour réserver, si besoin, des questions à un seul emploi (ex. diagnostic) ; par défaut tous les emplois.
  - **Quiz de validation (F13)** : `cert_validation_draw(p_unit_kind, p_unit_id, p_n)` tire `p_n` questions de la banque étiquetées par la notion ou le piège, en priorité celles que l'élève n'a pas encore répondues, jamais deux fois la même dans le même quiz.
- **Règles** : une question utilisée dans un test blanc en cours n'est jamais retirée de la banque (statut changé seulement entre deux tentatives) ; la couverture par notion (au moins 12 questions étiquetées) reste le critère de contenu ; le diagnostic garde son jeu réservé.
- **Acceptation** : AC-BANQUE-1 aucune question n'est dupliquée pour un test (les compositions ne contiennent que des références) ; AC-BANQUE-2 corriger une question la corrige dans tous les emplois ; AC-BANQUE-3 `cert_validation_draw` ne renvoie que des questions `reviewed` de la notion, sans doublon ; AC-BANQUE-4 `cert_question_usage` compte exactement les apparitions.
- **Tests** : pgTAP (vue d'usage, `cert_validation_draw`, pas de copie à la composition) ; Jest (tirage d'un quiz de validation).
- **Contenu** : le besoin de 800 questions neuves (v1.33) alimente cette banque unique ; elles sont étiquetées par notion en priorité (42 notions sous le seuil), puis réparties entre demi-tests, validations et parties selon l'usage.

## Listes de tests pour tous les types, refaire ou passer à un autre (version 1.35, 22 octobre 2026)

Demande de Benny (22 octobre, capture) : le principe « une liste de tests différents » vaut pour **tous** les types (mini-tests par partie, mini-tests mixtes, demi-tests Écoute et Lecture, tests complets), pas seulement les demi-tests. Pour chaque test, l'élève voit sa note, peut passer **un autre test** ou **refaire** celui-ci pour améliorer sa note.

- **D-50 Une liste par type** : chaque type ouvre une liste de tests numérotés et distincts : « Mini-test Partie 5 n° 3 », « Mixte n° 2 », « Écoute n° 4 », « Test complet n° 2 ». Chaque ligne : numéro, statut (D-36), dernier et meilleur score, tentatives, date, « {n} questions nouvelles pour toi » et « Conseillé » (D-46). Les mini-tests par partie demandent d'abord le choix de la partie (P1 à P7), puis ouvrent la liste de cette partie. En tête de chaque liste : « Faits : 2 sur 6 · Meilleur : … ».
- **D-51 Refaire ou passer à un autre** : depuis la ligne d'un test fait, le détail propose trois actions : « Voir ma note et mes tentatives », « Refaire pour améliorer ma note » (nouvelle tentative du même test, nouveau débit, 12.6.1) et « Passer un autre test » (ouvre le test **Conseillé** du même type, sinon la liste). À la fin d'un test, le bilan propose les mêmes deux boutons. **Le meilleur score est conservé** ; une tentative moins bonne ne le baisse pas ; une tentative meilleure affiche « Nouveau meilleur score » (en mots, sans couleur seule). La liste des tentatives est celle de D-47, par test. Une tentative d'Entraînement ne compte pas dans le meilleur score (5.M.1).
- **D-52 Composition par type, depuis la banque unique (D-49, F14 étendu)** : tout test est une composition figée de références à `cert_questions` (aucune copie) ; deux tests d'un même type et d'une même partie partagent au plus un pourcentage de questions : mini-test par partie 50 % (`{mini_max_overlap_pct}`), mixte 50 %, demi-test 50 questions (D-46), test complet 40 % (`{full_max_overlap_pct}`). Cibles dans `cert_settings` : `{mini_part_target}` 6 par partie, `{mini_mixed_target}` 6, `{half_target_count}` 7 par moitié, `{full_target_count}` 7. Un test qui ne peut pas être composé sans dépasser le recouvrement reste « Bientôt ». **Ce que la banque actuelle (600 questions) permet** : par partie, P1 18 questions (donc 3 à 4 mini-tests seulement), P2 75, P3 117, P4 90, P5 90, P6 48, P7 162 ; **mixtes** : 6 composables ; **demi-tests** : 6 par moitié (D-46) ; **tests complets** : seulement les 3 d'origine. Avec le lot de 800 questions neuves (v1.33) : tests complets n° 4 à 7 et toutes les cibles atteintes, y compris P1 qui reste la partie la plus pauvre (prévoir au moins 20 questions neuves de partie 1).
- **D-53 Plan et Statistiques** : le plan (D-42) propose à chaque étape de test le test **Conseillé** du type voulu ; il propose « Refaire pour améliorer » quand le meilleur score du test est sous `{retake_below}` (initial 60 % ou l'équivalent en score) et que le dernier essai date d'au moins `{retake_min_days}` jours (initial 3) ; jamais un test déjà fait tant qu'il en reste un jamais fait du même type. Statistiques affiche par type « Faits : x sur y » et le meilleur score par type ; la courbe (D-40) ne prend toujours que les demi-tests et tests complets (un mini-test ne crée pas de point). Le coût en crédits reste par tentative.
- **Données (généralisation de D-46)** : `cert_half_tests` devient **`cert_test_defs(id, kind, part, numero, titre, source, status, sort)`** avec `kind` : `mini_part`, `mini_mixed`, `half_listening`, `half_reading`, `full` ; `part` (1 à 7) seulement pour `mini_part` ; liens `cert_test_def_questions(test_def_id, question_id, number)` ; `cert_mock_attempts.test_def_id` (remplace `half_test_id` ; null pour l'existant) ; RPC `cert_test_compose(p_kind, p_part)` (service, idempotente, applique les recouvrements maximaux) et `cert_test_list_get(p_kind, p_part)` (par test : numéro, statut, tentatives, dernier et meilleur score, dernière date, `nouvelles`, `conseille`) ; `cert_mini_draw()` est remplacé par un test numéroté tiré dans la liste. Si le lot base D-46 est déjà écrit, il est **généralisé** par une migration additive (`kind` et `part` ajoutés, nom conservé en vue) ; sinon le dev crée directement les tables génériques. Rattrapage : les anciennes tentatives de mini-test, sans test numéroté, sont rattachées à un test « Ancien mini-test » par partie. Aucun module natif, aucun montant en dur.
- **Hors ligne** : liste et états gardés sur l'appareil ; un test se joue hors ligne si ses questions et audios sont préparés (sinon X4).
- **Évènements** : `cert_test_list_viewed { kind, part, faits, total }`, `cert_test_started { kind, numero, retake: bool }`, `cert_test_new_best { kind, numero }`.
- **Acceptation** : AC-LISTE-1 chaque type ouvre une liste de tests numérotés distincts, aucun doublon ; AC-LISTE-2 chaque ligne affiche statut, scores, tentatives et date ; AC-LISTE-3 « Refaire pour améliorer » crée une tentative du même test sans écraser le meilleur score ; AC-LISTE-4 « Passer un autre test » ouvre un test différent, de préférence « Conseillé » ; AC-LISTE-5 une tentative moins bonne ne baisse jamais le meilleur score ; AC-LISTE-6 une tentative meilleure affiche « Nouveau meilleur score » ; AC-LISTE-7 deux tests d'un même type et d'une même partie respectent le recouvrement maximal ; AC-LISTE-8 un test non composable est « Bientôt » ; AC-LISTE-9 les mini-tests par partie demandent la partie avant la liste.
