# Issue #74 — lot B : préchargement ciblé des séances J / J+1 / J+2

- Date : 2026-10-23 (UTC)
- Auteur : Muse
- Sujet : lot B de l'issue #74 rouverte (préchargement des séances des trois prochains jours)
- État : fait, validation locale verte, en attente de CI
- Zones touchées : `src/services/planning.ts`, `src/services/horsLigne.ts`, tests associés

## Constat de départ

Le pack hors ligne est global : `estimerTelechargement` construit une tâche par contenu du programme
entier de l'élève (fiches, leçons et leurs quiz de validation, quiz libres, exercices et corrigés,
documents PDF, missions des 7 prochains jours). Les séances du planning sont calculées côté serveur à
partir de ce même programme : tous leurs contenus sont donc déjà dans le pack quand l'élève télécharge
tout. Le « préchargement ciblé » se traduit par une **priorisation** : les contenus des séances
d'aujourd'hui, de demain et d'après-demain passent en tête de file, pour qu'un téléchargement
interrompu couvre déjà les séances imminentes.

## Ce qui est fait

- `planning.ts` : `idsTachesSeances(planning, jours)` — fonction pure qui rend, dans l'ordre des jours
  puis des éléments, les identifiants de tâches du pack pour les séances données : leçon →
  `lecon-<id>` + `validation-<id>`, quiz → `quiz-<id>`, exercice → `exercice-<id>` + `corrige-<id>`.
  Les annales et les révisions n'ont pas de contenu propre à télécharger par séance.
- `horsLigne.ts` : `prioriserTachesSeances(taches, ids)` — partition stable : missions en tête (ordre
  habituel), puis les tâches prioritaires, puis le reste du programme. `estimerTelechargement` lit le
  planning de l'élève connecté (session + `lirePlanning`), calcule les trois jours à partir du jour
  local et réordonne avant les estimations. Planning absent, non prêt ou illisible : aucun
  réordonnancement, le pack garde son ordre — le préchargement ne peut jamais bloquer le pack entier.

## Tests

- `planning.test.ts` : `idsTachesSeances` (contenus d'une séance, ordre des jours, dédoublonnage,
  jour sans séance).
- `horsLigne.test.ts` : `prioriserTachesSeances` (partition stable, sans priorité = ordre inchangé) et
  intégration `estimerTelechargement` (la séance du jour passe avant la fiche et le quiz libre ; sans
  planning prêt, l'ordre du programme est conservé).

## Limites connues (inchangées, règles du pack)

- Le corrigé d'un exercice n'entre dans le pack que si le pass est actif ou le corrigé déjà ouvert ;
  l'énoncé y est toujours.
- Un changement de programme après le téléchargement n'est pas couvert par l'ancien pack — c'est le
  lot C (garde hors ligne du changement de classe/programme).
