## Test d'intégration (`planningParcoursHorsLigne`)

Les vrais services (planning, connectivité, stockage) tournent ; seul le client
Supabase est remplacé par un faux serveur à état explicite (planning lu, coches
écrites, file de rejeu). Trois cas :

1. **Parcours complet** : lecture en ligne (la copie locale est gardée) → coupure
   (la copie est servie, pas d'erreur) → coche hors ligne (renvoyée « en attente »,
   rangée en file, visible sur la copie) → reconnexion (le rejeu part AVANT la
   relecture, la file est vidée, la séance revient cochée du serveur).
2. **En ligne direct** : la coche part tout de suite au serveur, rien en file.
3. **Sans copie locale** : l'erreur réseau remonte au lieu d'inventer un planning.

C'est le scénario de l'issue (§1 + §3) prouvé de bout en bout, là où les lots
précédents le couvraient par morceaux.
