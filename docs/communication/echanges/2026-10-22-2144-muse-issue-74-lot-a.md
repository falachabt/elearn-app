## Ce qui a été fait

**Spec d'abord** : la section 8 de `docs/maquettes/planning-etudes.md` (itération du 22 octobre 2026, validée par Benny) remplace la « lecture seule » hors ligne pour la coche de séance : écriture différée, rejeu idempotent, dernier état par jour, abandon si le jour a disparu côté serveur. Commit `ca6ecda` (docs, poussé avant le code).

**Code** (`src/services/planning.ts`) :
- File par utilisateur `planning.cochesEnAttente.<id>` : `{ jour, fait, le }`, une entrée par jour, le dernier état gagne (`lireCochesEnAttente`, `enregistrerCocheEnAttente`). Lecture défensive : une file illisible vaut une file vide.
- `basculerSeance(client, idUtilisateur, jour, fait)` : en ligne, le serveur confirme et retire une coche plus ancienne du même jour restée en file ; sans réseau, la coche part dans la file (`enAttente`) ; un jour inconnu du serveur reste l'erreur `jour_inconnu`, rien n'est mis en file.
- `synchroniserCoches(client, idUtilisateur)` : rejoue la file dans l'ordre via le RPC existant `study_plan_mark_done` (idempotent). Réponse « faux » (jour disparu après recalcul) : la coche est abandonnée, le serveur fait foi. Erreur réseau : arrêt immédiat, tout le reste demeure en file.
- `lirePlanning` rejoue la file avant sa lecture (l'état relu est à jour) et repose les coches restantes sur ce qui s'affiche (`appliquerCoches`), copie locale comme réponse serveur. La copie gardée reste celle du serveur : le recouvrement se refait à chaque lecture.
- Rejeu aussi déclenché à l'ouverture de session et à la connexion (`src/session/SessionProvider.tsx`), aux mêmes endroits que `synchroniserEntrainement`.

**Page séance** (`PlanningJour.tsx`) : les boutons « J'ai terminé ma séance » et « Marquer comme non faite » ne sont plus désactivés en mode copie ; la coche automatique (toutes les tâches validées) passe par la même file hors ligne ; en mode copie, la mention prévue par la spec s'affiche : « Tu es hors ligne : ta séance est gardée sur l'appareil, elle sera synchronisée au retour du réseau. » (clé `planning.horsLigneSynchro`, FR et EN). L'événement analytics `planning_day_checked` part dans les deux cas, comme avant.
